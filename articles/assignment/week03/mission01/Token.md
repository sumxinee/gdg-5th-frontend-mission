1. 등장 배경: HTTP의 비연결성 및 무상태성
-HTTP 프로토콜은 요청(Request)과 응답(Response)이 끝나면 연결을 끊는 Connectionless(비연결 지향) 및 Stateless(무상태) 특징을 가짐. 이로 인해 서버는 클라이언트가 누구인지, 이전에 어떤 작업을 했는지 기억하지 못함. 이를 보완하여 로그인 상태 등을 유지하기 위해 쿠키, 세션, 토큰을 사용함.

2. 쿠키(Cookie)
-개념: 클라이언트(브라우저)에 저장되는 키-값(Key-Value) 형태의 데이터 파일임.
-작동 방식
: 서버가 응답 헤더(Set-Cookie)에 저장하고 싶은 정보를 담아 보냄.
: 클라이언트는 이후 요청마다 헤더(Cookie)에 저장된 쿠키를 담아 보냄.
: 서버는 이를 통해 클라이언트를 식별함.
-특징
: 공개 가능한 정보를 사용자의 브라우저에 저장함.
: 보안에 취약할 수 있어 민감한 정보(비밀번호 등)는 직접 저장하지 않는 것이 좋음.

3. 세션(Session)
-개념: 민감한 정보를 쿠키 대신 서버 측에 저장하고, 클라이언트에게는 식별자인 Session ID만 부여하는 방식임.
-작동 방식
: 서버는 사용자 정보(비밀번호 등)를 서버에 저장하고, 이를 식별할 수 있는 Session ID를 생성함.
: 이 Session ID를 쿠키에 담아 클라이언트에게 보냄.
: 클라이언트가 Session ID를 보내면 서버는 내부 저장소에서 해당 ID와 매칭되는 사용자 정보를 찾음.
-특징
  -보안성: 인증 정보가 서버에만 있고 클라이언트는 ID만 가지므로 쿠키보다 안전함.
  -서버 부하: 사용자가 많아질수록 서버에 저장해야 할 정보가 늘어나고, 매칭에 시간이 걸려 서버 부하가 심해질 수 있음.

4. 토큰(Token / JWT)
-개념: 클라이언트의 인증 정보를 암호화하여 토큰 형태로 발급하고, 클라이언트가 이를 저장했다가 요청 시 제출하는 방식임. (주로 JWT: JSON Web Token 사용)
-구조: Header(검증 정보) + Payload(실제 데이터) + Signature(서명)
-특징 및 장점
  -무상태(Stateless) & 확장성: 토큰 자체에 검증 정보(Signature)와 데이터가 포함되어 있어, 서버가 별도의 저장소에서 상태를 관리할 필요가 없음. (서버 부하 감소)
  -위변조 방지: 서명(Signature)을 통해 데이터 위변조를 막을 수 있음.
  -호환성: JSON 형식을 사용하여 다양한 플랫폼(모바일 등)에서 처리가 쉬움.
-단점
  -네트워크 부하: 쿠키나 세션 ID보다 정보량이 많아 토큰 길이가 길어지면 트래픽에 영향을 줄 수 있음.
  -보안: Payload는 암호화되지 않으므로 민감한 정보를 담으면 안 됩니다. 또한, 토큰이 탈취되면 만료될 때까지 대처하기 어려움(강제 로그아웃 처리가 어려움).
-보안 전략
: 짧은 만료 기간 설정, Sliding Session(자동 연장), Refresh Token(재발급용 토큰) 활용.

**정리**
-쿠키: 정보가 브라우저에 있어 빠르지만 보안에 취약.
-세션: 보안은 좋지만 사용자가 많으면 서버가 힘들어짐.
-토큰: 서버 부하를 줄이고 확장성이 좋으나, 토큰 관리(길이, 탈취)에 주의 필요.
