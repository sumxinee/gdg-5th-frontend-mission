1. 동기(Synchronous) vs 비동기(Asynchronous)
두 방식의 가장 큰 차이는 작업 처리의 흐름과 대기 여부임.
-동기(Synchronous): '직렬적' 처리 방식
  -개념: 요청을 보낸 후 응답을 받아야만 다음 동작이 이루어짐.
  -특징: 한 번에 하나의 태스크만 처리하며, 현재 태스크가 끝날 때까지 다음 태스크는 대기해야 함.
  -장단점: 설계가 직관적이지만, 앞선 작업이 오래 걸리면 시스템 전체 효율이 떨어질 수 있음.
-비동기(Asynchronous): '병렬적' 처리 방식
  -개념: 요청을 보낸 후 응답 수락 여부와 상관없이 즉시 다음 태스크를 실행함.
  -특징: 특정 코드가 완료될 때까지 멈추지 않고 다음 코드를 먼저 실행함. (예: Ajax, setTimeout 등)
  -장단점: 자원을 효율적으로 사용할 수 있지만, 작업 순서를 보장하기 위해 콜백 함수를 중첩하다 보면 **콜백 헬(Callback Hell)**이 발생하여 코드가 복잡해질 수 있음.

2. Promise(프로미스)
ES6에서 도입된 비동기 처리를 위한 객체로, 콜백 헬 문제를 해결하고 비동기 처리 시점을 명확하게 표현하기 위해 사용됨.
-3가지 상태(State)
  -Pending (대기): 비동기 처리가 아직 수행되지 않은 상태
  -Fulfilled (이행): 비동기 처리가 성공적으로 수행된 상태 (resolve 호출)
  -Rejected (거부): 비동기 처리가 실패한 상태 (reject 호출)
-사용 방법
  -생성: new Promise((resolve, reject) => { ... }) 형태로 생성하며, 성공 시 resolve(), 실패 시 reject()를 호출함.
  -후속 처리
    -.then(): 성공 시 실행될 콜백과 실패 시 실행될 콜백을 받음. (주로 성공 처리용으로 사용)
    -.catch(): 비동기 처리나 .then에서 발생한 에러(예외)를 처리함.
  -체이닝 (Chaining): .then() 메서드는 항상 Promise를 반환하므로, 이를 연결하여 여러 비동기 작업을 순차적으로 처리할 수 있어 콜백 헬을 방지함.

3. Async / Await
Promise를 기반으로 하지만, 더 읽기 쉽고 직관적인(마치 동기 코드처럼 보이는) 문법을 제공함.
-async
: 함수 앞에 붙여 사용함. (async function 함수명() {})
: 해당 함수는 항상 Promise를 반환함. (일반 값을 리턴해도 이행된 Promise로 감싸서 반환됨)
-await
: async 함수 내부에서만 사용할 수 있음.
: Promise가 처리(settled)될 때까지 함수 실행을 일시 중단하고 기다림.
: Promise가 이행되면 그 결과 값을 반환하고 코드를 재개함.
: 비동기 처리 중에도 엔진이 다른 스크립트를 실행할 수 있어 CPU 리소스를 낭비하지 않음.
-에러 처리
: try...catch 문을 사용하여 일반적인 동기 코드처럼 에러를 잡아낼 수 있음.

**요약**
-동기/비동기: 작업의 순차적 진행 여부와 대기 여부의 차이.
-Promise: 비동기 작업의 상태를 관리하고 콜백 헬을 해결하는 객체.
-Async/Await: Promise를 더 편하고 가독성 좋게 사용하기 위한 최신 문법 (동기 코드처럼 작성 가능).

4. 핵심 개념 구분
-동기/비동기(Synchronous / Asynchronous)
  -관점: 작업의 순서와 결과 처리(Timing & Result)
  -동기: 요청한 작업이 끝날 때까지 기다렸다가, 완료 여부를 확인하고 다음 작업을 순차적으로 실행함. (작업 A 완료 → 작업 B 시작)
  -비동기: 요청한 작업의 완료 여부를 신경 쓰지 않고, 바로 다음 작업을 실행함. (작업 A 시작 → 즉시 작업 B 시작, A 결과는 나중에 콜백 등으로 받음)
-블로킹/논블로킹 (Blocking / Non-Blocking)
  -관점: 제어권(Control)의 위치 (Flow Control)
  -블로킹: 호출된 함수가 작업을 마칠 때까지 제어권을 가지고 놓아주지 않음. 호출한 쪽은 아무것도 못 하고 대기(Block)해야 함.
  -논블로킹: 호출된 함수가 제어권을 즉시 반환. 호출한 쪽은 다른 작업을 계속 수행할 수 있음.

5. 4가지 조합(IBM Matrix 모델)
이 두 가지 관점이 결합되어 총 4가지의 동작 방식이 만들어짐.
-Sync + Blocking (동기 + 블로킹)
  -특징: 가장 일반적인 동기 방식. 작업이 끝날 때까지 제어권도 안 주고(Blocking), 결과도 기다렸다가 다음으로 넘어감(Sync).
  -상황: 팀장이 사원에게 업무를 시키고, 끝날 때까지 옆에서 아무것도 안 하고 기다리다가 끝나면 다음 업무를 시킴.
  -예시: Java의 기본적인 입출력(Scanner), C언어 콘솔 프로그램.
-Async + Non-Blocking (비동기 + 논블로킹)
  -특징: 가장 효율적인 비동기 방식. 작업을 시키고 제어권을 바로 받아 다른 일을 하다가(Non-Blocking), 작업이 끝났다는 알림(콜백)이 오면 결과를 처리(Async).
  -상황: 팀장이 사원에게 업무를 시키고 자기 할 일을 하다가, 사원이 "다 했습니다"라고 메신저를 보내면 그때 확인.
  -예시: JavaScript의 AJAX 요청, Node.js의 비동기 처리, 웹 브라우저 파일 다운로드.
-Sync + Non-Blocking (동기 + 논블로킹)
  -특징: 제어권은 바로 돌려받아 다른 일을 할 수 있지만(Non-Blocking), 작업 결과가 궁금해서 계속 확인하는(Sync) 방식. **Polling(폴링)**이라고도 함.
  -상황: 팀장이 사원에게 업무를 시키고 자기 일을 하지만, 계속 "다 했어?", "아직?", "다 했어?"라고 물어보며 확인.
  -예시: Java/Python에서 스레드를 실행시키고 while문으로 완료 여부를 계속 확인하는 경우, 게임 로딩 화면(데이터 로드율 체크).
-Async + Blocking (비동기 + 블로킹)
  -특징: 비동기(결과를 나중에 처리하려 함)임에도 불구하고, 블로킹(제어권을 뺏김) 되어버리는 비효율적인 상황. 보통 의도해서 쓰기보다 실수나 기술적 한계로 발생함.
  -상황: 팀장이 사원에게 "결과 나오면 나중에 메일 줘(Async)"라고 해놓고, 정작 사원이 일하는 동안 옆에서 멍하니 서 있음(Blocking).
  -예시: Node.js와 MySQL 드라이버 연동 시 발생하는 오버헤드, Java의 비동기 코드에서 Future.get()을 호출해 억지로 결과를 기다리게 만드는 경우.

6. 콜백 함수(Callback Function)란?
-정의: 다른 함수에 인자(Argument)로 전달되는 함수를 말합니다. 이렇게 전달된 함수는 외부 함수의 내부에서 실행(invoke)됨.
-핵심 원리: 자바스크립트에서 함수는 **객체(Object)**임. 따라서 함수는 변수에 저장될 수 있고, 다른 함수의 인자로 전달될 수도 있으며, 함수의 결과로 반환될 수도 있음. (이를 일급 객체라고 함.)

7. 왜 콜백 함수를 사용하는가? (등장 배경)
-자바스크립트는 기본적으로 코드를 위에서 아래로 순차적으로 실행함. 하지만 비동기 처리나 특정 시점 이후에 실행되어야 하는 코드가 필요할 때 콜백을 사용함.
  -이벤트 처리: "사용자가 버튼을 클릭했을 때" 실행.
  -타이머: "3초 뒤에" 실행.
  -서버 통신: "데이터를 받아오면" 실행.
-자바스크립트는 싱글 스레드 언어임. 즉, 한 번에 하나의 작업만 할 수 있음. 만약 콜백을 사용하지 않고 오래 걸리는 작업(예: 서버 데이터 요청)을 기다린다면, 브라우저는 멈춰버릴 것임. 콜백을 사용하면 "이 작업이 끝나면, 이 함수를 실행해줘(Call me back)"라고 맡겨두고 다음 코드를 계속 실행할 수 있음.

8. 콜백 함수 사용 방법 및 주의점
-기본 구조
function print(callback) { // 1. 함수를 인자로 받음
    callback(); // 2. 내부에서 해당 함수를 실행
}

-중요: 함수를 전달할 때의 문법
-콜백으로 함수를 넘길 때는 괄호 ()를 붙이면 안 됨.
  -O (옳은 방법): myFunction (함수 자체를 전달)
  -X (틀린 방법): myFunction() (함수의 실행 결과를 전달하게 됨)
// 예시: 3초 뒤에 메시지 출력
const message = function() {
    console.log("3초 뒤에 실행됩니다.");
}

setTimeout(message, 3000); // message 함수 자체를 넘김 (O)
// setTimeout(message(), 3000); // 함수가 즉시 실행되어버림 (X)

9. 동기적 콜백 vs 비동기적 콜백
-동기적(Synchronous) 콜백: 즉시 실행되는 콜백임.
  -예: Array.prototype.map, filter 등 배열 메서드에 들어가는 함수들.
-비동기적(Asynchronous) 콜백: 나중에(비동기 작업 완료 후) 실행되는 콜백임.
  -예: setTimeout, addEventListener, 데이터 페칭(Fetch) 등.

10. 콜백 지옥 (Callback Hell)
-비동기 작업을 순차적으로 처리하기 위해 콜백 함수 안에 또 다른 콜백 함수를 계속 중첩하면, 코드가 옆으로 길어지고 가독성이 매우 떨어지는 현상이 발생함. 이를 **'콜백 지옥'**이라고 부름.
// 콜백 지옥의 예시 (가독성이 나쁨)
step1(function(value1) {
    step2(value1, function(value2) {
        step3(value2, function(value3) {
            // ... 계속되는 중첩
        });
    });
});
-해결책: 이 문제를 해결하기 위해 ES6부터는 Promise, 이후 Async/Await 문법이 도입되었음.

**요약**
-콜백 함수는 다른 함수의 인자로 넘겨주는 함수임.
-자바스크립트 함수는 객체이기 때문에 이것이 가능함.
-함수를 넘길 때는 이름만 쓰고 ()는 뺌.
-비동기 작업(타이머, 이벤트, 서버 통신 등)을 처리할 때 필수적임.
-과도한 사용은 콜백 지옥을 유발하므로 Promise나 Async/Await으로 대체하는 추세임.
